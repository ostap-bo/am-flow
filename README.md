# AM Flow

Особиста CRM акаунт-менеджера: картки клієнтів і покроковий робочий флоу з перемикачами, термінами, шаблонами повідомлень (УКР / РУС / ENG) та історією дій.

- **Флоу етапів** спільний для всіх клієнтів і редагується в «Налаштуваннях». Зміни одразу діють для всіх карток, позначений прогрес зберігається.
- **Пункти** вмикаються перемикачем («виконано» з датою). Щоб зняти позначку, потрібне підтвердження. Пункт можна позначити як «не потрібно для цього клієнта» або додати окремий пункт лише для одного клієнта.
- **Матеріали до пункту**: шаблони повідомлень трьома мовами з кнопкою «Копіювати», файли й посилання. Змінні на кшталт `{{клієнт}}` чи `{{контакт}}` підставляються з картки клієнта.
- **Картка клієнта**: поля (налаштовуються), нотатки з датами, файли, історія.
- **Огляд**: прострочене, терміни на тиждень, прогрес клієнтів, остання активність.
- Світла й темна теми, адаптивний інтерфейс для телефона.

Дані зберігаються у **вашому** проєкті Firebase (синхронізація між пристроями й робота офлайн) або лише в браузері (локальний режим). У цьому репозиторії немає жодних даних клієнтів і жодних шаблонів: лише код.

---

## 1. Публікація на GitHub Pages

1. Завантажте файли репозиторію в гілку `main`.
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch**, гілка `main`, папка `/ (root)` → **Save**.
3. За хвилину-дві сайт буде доступний за адресою `https://<ваш-логін>.github.io/<назва-репозиторію>/`.

## 2. Налаштування Firebase (один раз, ≈10 хвилин)

1. Відкрийте [console.firebase.google.com](https://console.firebase.google.com) → **Create a project** (Google Analytics можна вимкнути).
2. **Build → Authentication → Get started → Sign-in method → Email/Password → Enable → Save.**
3. **Authentication → Users → Add user**: ваш email і пароль. Реєстрації в застосунку немає, тому акаунт створюється тут.
4. **Authentication → Settings → Authorized domains → Add domain**: `<ваш-логін>.github.io`.
5. **Build → Firestore Database → Create database**: оберіть розташування в Європі (наприклад, `eur3`), режим **production**.
6. **Firestore → Rules**: вставте вміст файлу [`firestore.rules`](firestore.rules), замініть `YOUR_EMAIL@example.com` на свій email → **Publish**.
7. **Project settings (⚙) → General → Your apps → Web (`</>`)**: зареєструйте застосунок (Hosting не потрібен) і скопіюйте блок `firebaseConfig`.

Платний тариф Blaze **не потрібен**. Файли зберігаються частинами прямо у Firestore (до 10 МБ на файл), тож вистачає безкоштовного тарифу Spark (1 ГБ даних).

## 3. Підключення

**Варіант А, рекомендований.** Відкрийте `index.html` і в блоці `<head>` замініть

```js
window.AMFLOW_FIREBASE_CONFIG = null;
```

на свій конфіг:

```js
window.AMFLOW_FIREBASE_CONFIG = {
  apiKey: "…",
  authDomain: "…",
  projectId: "…",
  storageBucket: "…",
  messagingSenderId: "…",
  appId: "…"
};
```

Ці ключі не секретні: вони лише вказують, до якого проєкту звертатися. Доступ до даних захищають вхід і правила `firestore.rules`. Після цього на будь-якому пристрої достатньо відкрити сайт і ввести email та пароль.

**Варіант Б.** Залиште `null`: при першому відкритті застосунок попросить вставити `firebaseConfig`. Тоді це доведеться зробити на кожному пристрої.

## 4. Перший запуск

1. Увійдіть за email і паролем із кроку 2.3.
2. **Налаштування → Флоу етапів → Імпорт флоу**: оберіть файл флоу (`.json`), якщо він у вас є, або створіть етапи вручну.
3. **Налаштування → Змінні**: впишіть своє ім'я в змінну `ам`.
4. **Новий клієнт**, і можна працювати.

## Резервні копії

**Налаштування → Дані → Експортувати** зберігає все (флоу, клієнтів, нотатки, історію, файли) в один `.json`. Ним же можна відновити дані або перенести їх із локального режиму в Firebase. Не завантажуйте такі файли в цей репозиторій: `.gitignore` уже їх виключає.

## Структура

```
index.html          ← зібраний застосунок з усім вбудованим (для роботи сайту достатньо лише його)
vendor/firebase.js  ← Firebase SDK 13.4.0 (Auth + Firestore); вбудовується в index.html під час збирання
firestore.rules     ← правила безпеки для Firestore
src/                ← вихідний код: стилі та модулі JS
tools/build.py      ← збирає src/ в index.html: python3 tools/build.py
build/              ← як перезібрати vendor/firebase.js: cd build && npm install && npm run build
```

Якщо редагуєте `src/`, після змін запустіть `python3 tools/build.py`. Збереження конфігу Firebase в `index.html` (варіант А) треба повторити після кожного перезбирання, або впишіть його в `src/shell.html`.
